# Политики категорий закупок: черновик

Дата фиксации: 2026-05-26.

## Зачем нужен этот слой

`ПокрытиеФакт` отвечает на вопрос:

```text
На сколько месяцев фактического спроса хватит текущего остатка?
```

Но это еще не норма. Для нормы нужно понимать физику категории:

- сколько дней занимает поставка;
- как часто категорию можно закупать;
- есть ли сезонное окно;
- какая минимальная партия;
- какой страховой запас нужен;
- есть ли срок годности;
- есть ли складской лимит;
- какой источник спроса допустим для этой категории.

Поэтому следующий слой - не коэффициенты, а политики категорий.

## Поля политики

Минимальная таблица политики:

| Поле | Смысл |
|---|---|
| `ОрганизацияНормы` | Юниант / Финист |
| `КатегорияНормы` | Категория из отчета |
| `ТипЕдиницыКонтроля` | `кг` или `усл.ед.` |
| `ТипПолитики` | Обычная / Сезонная / Партийная / Проверить |
| `ИсточникСпросаОсновной` | Производственный расход / План ГП через рецептуры / Закупки поставщиков / Ручной прогноз |
| `СрокПоставкиДней` | Сколько дней от решения до прихода |
| `ПериодМеждуЗакупкамиДней` | Как часто реально закупается категория |
| `СтраховойЗапасДней` | Буфер на сбой поставки и колебание спроса |
| `МинимальнаяПартия` | Минимальный размер закупки |
| `КратностьПартии` | Кратность заказа |
| `СезонноеОкно` | Месяцы, когда сырье реально закупается |
| `ГоризонтСезонаДней` | До какого следующего окна надо покрыть спрос |
| `СрокГодностиДней` | Ограничение на максимальный запас |
| `ЛимитСклада` | Физический складской лимит |
| `СтатусПолитики` | Готова / Требует решения / Нужна рецептура / Нужен план |

## Предварительные наблюдения по `ПокрытиеФакт`

Это не решения и не рекомендации. Это список мест, где политика нужна в первую очередь.

### Финист

| Категория | Покрытие | Что проверить |
|---|---:|---|
| `кг всего` | `0,97 мес` | Близко к одному месяцу. Нужен срок поставки и страховой запас. |
| `Ингредиенты` | `1,30 мес` | Похоже на обычную регулярную категорию. Нужна частота закупки. |
| `Ингредиенты (ВетИс)` | `0,62 мес` | Может быть дефицит, если нет короткого срока поставки. |
| `Птица` | `0,90 мес` | Критично проверить срок поставки и недельную волатильность. |
| `Сыры (молочная продукция)` | `0,13 мес` | Похоже на дефицит или проблему классификации спроса/остатка. |
| `Рыба` | спрос есть, остатка нет | Проверить, не лежит ли остаток в другой категории или на другом складе. |
| `Субпродукт (из рыбы и морепродуктов)` | спрос есть, остатка нет | Проверить соответствие категорий Финиста и Юнианта; категория слишком укрупнена. |
| `Материалы: Тара/Упаковка` | `1,13 мес` | Нужна политика по партиям и частоте закупки. |

| Категория | Покрытие | Что проверить |
|---|---:|---|
| `кг всего` | `2,07 мес` | В целом запас выше Финиста, но внутри большие перекосы. |

| `Морепродукты: кальмары` | `0,21 мес` | Сезонная/партийная категория. Нужен календарь окна закупки и прогноз до следующего окна. |
| `Морепродукты: креветки` | `36,16 мес` | Возможный избыток, нерегулярный спрос или неверный источник спроса. |
| `Рыба: лососевые` | `0,08 мес` | Проверить, не попадает ли потребление/остаток в `Субпродукт: лососевые`. |
| `Рыба: тресковые` | `3,92 мес` | Может быть нормой для сезонной/партийной закупки, но нужно правило. |

| `Субпродукт: кальмары` | `1,49 мес` | Связать с политикой кальмара, возможно общая сезонная группа. |
| `Субпродукт: лососевые` | `1,28 мес` | Проверить вместе с `Рыба: лососевые`. |
| `Субпродукт: тресковые` | `2,26 мес` | Вероятно регулярная/партийная категория, нужна частота закупки. |
| `Субпродукт: тунцы` | `10,82 мес` | Возможный избыток или нерегулярное сырье. |
| `Материалы: Тара/Упаковка` | `4,92 мес` | Выглядит запасенной категорией, но надо учитывать партии и поставщиков. |

## Формула после заполнения политики

Для обычной категории:

```text
СпросВДень = СпросВМесяц / 30

Min =
    СпросВДень * (СрокПоставкиДней + СтраховойЗапасДней)

Target =
    СпросВДень * (СрокПоставкиДней + ПериодМеждуЗакупкамиДней + СтраховойЗапасДней)

Max =
    Target + МинимальнаяПартия + БуферПоставки
```

Для сезонной категории:

```text
Target =
    ПрогнозСпросаДоСледующегоОкнаЗакупки + СтраховойЗапас

Max =
    Target + ДопустимыйПартийныйБуфер
```

## Технический статус

Ранний план предполагал отдельный слой `ПолитикиКатегорий` в СКД. После рефакторинга этот слой не выводится наружу: финальные рабочие варианты отчета используют только `КонтрольНормы` и `КонтрольКонтура`, а политика категории остается внутренней частью расчета нормы.

Если политики будем согласовывать отдельно, это лучше делать через отдельную таблицу настроек/справочник расширения. В ней по каждой категории нужны поля:

```text
ПокрытиеМес
ТипПолитики
ИсточникСпросаОсновной
СрокПоставкиДней
ПериодМеждуЗакупкамиДней
СтраховойЗапасДней
МинимальнаяПартия
СезонноеОкно
СтатусПолитики
```

Пока значения политики не заполнены, отчет должен явно показывать `Требует решения`, а не молча считать норму по выдуманным коэффициентам.
