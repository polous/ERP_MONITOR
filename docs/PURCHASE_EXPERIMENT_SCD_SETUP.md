# Настройка СКД `MON_МониторЗакупокЭксперимент`

Отчет использует внешний набор данных-объект.

Модуль объекта отчета:

```text
МОДУЛЬ_ОБЪЕКТА_ОТЧЕТА_ЗАКУПОК_ЭКСПЕРИМЕНТ.txt
```

Имя объекта, содержащего данные:

```text
МониторЗакупок
```

## 1. Набор данных

Вкладка `Наборы данных`.

Создать набор данных типа `Объект`.

Рекомендуемое имя набора:

```text
НД_МониторЗакупок
```

Внизу указать:

```text
Имя объекта, содержащего данные = МониторЗакупок
```

Параметры набора данных не заполнять. Параметр `ДатаОтчета` задается на вкладке `Параметры` схемы компоновки.

После перехода на финальные слои `КонтрольНормы` и `КонтрольКонтура` полный старый список полей больше не обязателен. Список полей, которые можно удалить из ручной настройки СКД, вынесен в `docs/PURCHASE_SCD_DELETE_LIST.md`.

- `Путь` = то же имя;
- `Роль` не заполнять;

1. Добавить поле `ЦенаСредняя` на вкладке `Наборы данных`.
2. Перенести `ЦенаСредняя` в ресурсы.
3. В строке ресурса заменить выражение агрегации на:

```text
Окр(ВЫБОР КОГДА Сумма(КоличествоСЦеной) = 0 ТОГДА 0 ИНАЧЕ Сумма(СтоимостьРуб) / Сумма(КоличествоСЦеной) КОНЕЦ, 2)
```

## 7. Рабочие варианты отчета

После рефакторинга модуль объекта возвращает наружу только финальные слои:

- `КонтрольНормы` - детализация по категориям нормы;
- `КонтрольКонтура` - компактный управленческий итог по контурам `Финист` / `Юниант`.
- `СверкаExcelНормы` - диагностический слой расхождений между нашей физической нормой и Excel-подобной нормой закупщиков.

Слои `Остатки`, `СпросФизический`, `ПокрытиеФакт`, `ПрофильСезонности`, `СводСезонности`, `ПрофильПоставок`, `БазаНормы` остаются внутренними этапами расчета в модуле объекта. Отдельные варианты СКД под них больше не нужны: они пустеют после финальной отсечки данных и должны быть удалены из настроек отчета, если были созданы вручную.

В обработке монитора используются два перехода:

- заголовок `ЗАКУПКИ` открывает вариант `КонтрольКонтура`;
- заголовки `Юниант:` и `Финист:` открывают вариант `Итог`, который должен быть настроен как слой `КонтрольНормы`.

В форме обработки привязать клики так:

| Элемент формы | Событие | Обработчик |
| --- | --- | --- |
| `Дец_ЗакупкиЗаголовок` | `Нажатие` | `Дец_ЗакупкиЗаголовокНажатие` |
| `Дец_ЗакупкиЮниантЗаголовок` | `Нажатие` | `Дец_ЗакупкиЮниантЗаголовокНажатие` |
| `Дец_ЗакупкиФинистЗаголовок` | `Нажатие` | `Дец_ЗакупкиФинистЗаголовокНажатие` |

Если вместо событий используются команды формы, можно привязать команды напрямую:

- для `ЗАКУПКИ` - `ОткрытьОтчетЗакупокКонтуры`;
- для `Юниант:` и `Финист:` - `ОткрытьОтчетЗакупокИтог`.

Ключи вариантов должны совпадать с именами вариантов в СКД: `КонтрольКонтура` и `Итог`. Не синонимы, не представления, а именно имя варианта.

`ДатаОтчета` передается из формы монитора в пользовательские настройки отчета процедурой `ПодготовитьНастройкиЗакупок()`. Сам виджет при открытии монитора и смене даты отчет не формирует: отчет создается только внутри процедур открытия по клику.

Как читать:

- `НормаExcelФайл*` - эталон из текущих Excel-файлов закупщиков, зашитый в диагностический слой.
- `НормаExcelРасчет*` - Excel-подобная норма по нашим данным спроса и коэффициентам закупщиков.
- `ФакторКоличестваКExcel` больше `2` означает, что наша физическая норма минимум вдвое выше Excel.
- `ФакторЦеныКExcel` больше `2` означает, что наша цена контроля минимум вдвое выше Excel.
- `МесяцевПокрытияНашаНорма` против `МесяцевПокрытияExcel` показывает, сколько месяцев запаса держит наша модель и сколько фактически держит Excel.

Ограничение зрелости не режет кг-норму по складскому лимиту. Складские ориентиры `Юниант 500 т` и `Финист 150 т` используются как отдельный контекст загрузки склада, а не как расчет закупочной нормы.

В расчетной норме сейчас ограничивается только стартапный риск Финиста:

- период пополнения не выше `60` дней для обычных категорий;
- период пополнения не выше `90` дней для сезонных и партийных категорий;
- пиковый буфер не выше одного среднемесячного спроса категории.
- целевое покрытие не выше `1,5` месяца для обычных категорий;
- целевое покрытие не выше `1,25` месяца для малых категорий;

Расчетная сезонность Финиста сейчас не расширяет целевое покрытие сверх `1,5` месяца. Для стартапа сезонность по короткой истории считается недоказанной, пока нет отдельного календаря закупочных окон, длинного lead time или обязательной минимальной партии.

Поэтому в вариантах `Итог`, `КонтрольКонтура` и `СверкаExcelНормы` рублевая норма должна меняться только через физическую норму категории, а не через прямое масштабирование по складским тоннам.

Рублевая норма считается через цену нормы. Основной источник цены - средняя цена поставки за референсный период:

```text
ЦенаНормы = СтоимостьПоставки / КоличествоПоставки
```

Если поставочной цены по категории нет, используется резервная цена текущего остатка:

```text
ЦенаНормы = ОстатокРуб / ОстатокКонтроль
```

В набор данных добавлено поле `СтоимостьПоставки`. Его можно не выводить в основных вариантах, но оно полезно в диагностике цены нормы.
## 8. Вариант `КонтрольНормы`

Это управленческий слой: он соединяет текущие остатки из `ПокрытиеФакт` и расчетный коридор из `БазаНормы`.

Отбор:

```text
СлойДанных = КонтрольНормы
```

Структура:

```text
Отчет
  КонтурБизнеса
    ОрганизацияНормы
      ТипЕдиницыКонтроля
        СтатусКоридораНормы
          ТипПолитики
            КатегорияНормы
```

Выбранные поля:

```text
КатегорияНормы
РекомендацияНормы
ОстатокКонтроль
НормаМинКонтроль
НормаЦельКонтроль
НормаМаксКонтроль
ЦенаКонтроль
ОстатокРубКонтроль
НормаМинРубКонтроль
НормаЦельРубКонтроль
НормаМаксРубКонтроль
ДефицитДоМинимума
ОтклонениеОтЦели
ИзлишекСверхМаксимума
ДефицитДоМинимумаРуб
ОтклонениеОтЦелиРуб
ИзлишекСверхМаксимумаРуб
ПокрытиеЦелиНормы
ПокрытиеЦелиРубНормы
СтрокБезЦены
```

Для компактного варианта без детальных записей:

- убрать группировки `СтатусКоридораНормы` и `ТипПолитики`;
- оставить структуру `КонтурБизнеса -> ТипЕдиницыКонтроля -> КатегорияНормы`;
- `РекомендацияНормы` добавить в ресурсы как `Максимум(РекомендацияНормы)` и вывести в выбранных полях группировки `КатегорияНормы`;
- детальные записи выключить;
- `СтатусКоридораНормы` и `ПериодНормы` не выводить как детальные поля.

Логика статуса:

```text
Не нормируется -> хвостовая категория
Нет нормы -> целевая норма не рассчитана
Дефицит -> остаток ниже Min
Ниже цели -> остаток между Min и Target
Норма -> остаток между Target и Max
Избыток -> остаток выше Max
```

Для статусов `Не нормируется` и `Нет нормы` отклонения от цели, дефицит и избыток заполняются нулями: эти строки нельзя смешивать с нормируемой потребностью.

`Норма*Контроль` и `ОстатокКонтроль` - количественные поля. Их можно читать внутри одного `ТипЕдиницыКонтроля`, но нельзя сравнивать с рублями и нельзя трактовать общий итог как деньги. Для денежного сравнения используются `ОстатокРубКонтроль`, `НормаМинРубКонтроль`, `НормаЦельРубКонтроль`, `НормаМаксРубКонтроль`, `ОтклонениеОтЦелиРуб`, `ПокрытиеЦелиРубНормы`.

`ПокрытиеЦелиНормы` на верхнем итоге при смешении кг и усл. ед. лучше скрывать. Для верхнего итога используем `ПокрытиеЦелиРубНормы`.

Этот вариант уже можно использовать как прототип будущего блока закупок в виджете: он отвечает не просто "сколько лежит", а "что с этим делать".

## 9. Вариант `КонтрольКонтура`

Это верхний слой для будущего виджета. Он не показывает категории, а дает одну строку по контуру бизнеса: отдельно рубли, кг и усл. ед., плюс текстовую рекомендацию по комбинации факторов.

Важно: остатки контура считаются по всем категориям, включая `Нет нормы` и `Не нормируется`, чтобы сумма совпадала с общим складским остатком. Норма и покрытие считаются только по категориям, для которых норма реально рассчитана. Поэтому счетчики категорий без нормы нужно смотреть рядом с покрытием: они объясняют, какая часть остатка пока не участвует в нормативной модели.

### 9.3. Как оформить вариант отчета

Отбор:

```text
СлойДанных = КонтрольКонтура
```

Структура:

```text
Отчет
  КонтурБизнеса
```

Выбранные поля:

```text
ОстатокРубКонтроль
НормаЦельРубКонтроль
ОтклонениеОтЦелиРуб
ПокрытиеЦелиРубНормы
ОстатокКгКонтура
НормаЦельКгКонтура
ОтклонениеКгКонтура
ПокрытиеКгКонтура
ОстатокУслЕдКонтура
НормаЦельУслЕдКонтура
ОтклонениеУслЕдКонтура
ПокрытиеУслЕдКонтура
СтатусРубКонтура
СтатусКгКонтура
СтатусУслЕдКонтура
РекомендацияКонтура
КатегорийДефицит
КатегорийНижеЦели
КатегорийИзбыток
КатегорийНетНормы
КатегорийНеНормируется
```

Детальные записи для этого варианта не нужны. Если включить детальные записи, отчет начнет показывать служебную строку слоя, а не компактный вид для виджета.

Интерпретация:

```text
Рубли ниже цели + физика ниже цели -> общий дефицит
Рубли ниже цели + физика выше цели -> структурный перекос: много массы, мало нужной стоимости/ассортимента
Рубли выше цели + физика ниже цели -> дорогой запас при физическом дефиците
Рубли выше цели + физика выше цели -> профицит
Рубли в норме + одна физика ниже, другая выше -> физический перекос
```

Категории без нормы не участвуют в сумме нормы контура, но их остатки входят в общий остаток контура. Это сделано сознательно: директор должен видеть весь складской остаток, а методологический долг показывается счетчиками `КатегорийНетНормы` и `КатегорийНеНормируется`.

Итоговую строку СКД по всем контурам лучше не использовать для текстовых статусов и рекомендаций: строковые ресурсы агрегируются через `Максимум(...)`, поэтому общий итог может выбрать один из текстов, а не рассчитать новую управленческую рекомендацию. Для виджета и контроля смотреть строки `Финист` и `Юниант`.

Чтобы скрыть строку `Итого` в варианте `КонтрольКонтура`:

1. Открыть вариант `КонтрольКонтура` на вкладке `Настройки`.
2. Выделить самый верхний узел `Отчет`.
3. Перейти в нижнюю вкладку `Другие настройки`.
4. Найти настройки общих итогов и поставить:
   - `Расположение общих итогов по вертикали` = `Нет`;
   - `Расположение общих итогов по горизонтали` = `Нет`, если поле есть.
5. Если в конкретной версии платформы этих полей нет, искать близкую настройку `Выводить общий итог` / `Выводить итоги` и поставить `Нет`.

Строки `Финист` и `Юниант` останутся, исчезнет только общий итог по отчету.

## 10. Что сверять после запуска

Первый контроль:

```text
Контур Юниант: ОстатокРуб и ОстатокКг
Контур Финист: ОстатокРуб и ОстатокКг
Эрион: должен быть отдельным контуром, не смешанным с Юниантом/Финистом
СтрокБезЦены: должны быть видны, а не исчезать из отчета
```

Ожидаемо, рубли могут отличаться от текущего виджета, потому что экспериментальный отчет использует взвешенную цену и не отбрасывает физические строки без цены.
